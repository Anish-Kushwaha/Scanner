RESPONSIBLE USE · SCOPE · LIMITATIONS

Security assessment is a permission-based activity.

Scanner is a low-impact HTTP security-posture checker. It is not an authorization service, a guarantee of security, or a substitute for a properly scoped professional penetration test.

Only scan systems you own or are explicitly authorized to assess.
The confirmation checkbox records your attestation only. It does not verify ownership, grant permission, or make an otherwise unauthorized test lawful.

What the hosted scanner does

  • Fetches the requested public HTTP or HTTPS page on standard ports 80 and 443.
  • Checks TLS certificate verification/expiry information, selected HTTP security headers, cookie attributes, and limited technology indicators.
  • Validates DNS destinations, blocks non-public address space, pins requests to the validated IP, and rechecks redirect destinations.
  • Applies request timeouts, response limits, redirect limits, and a rate limit at the Vercel edge.

What it deliberately does not do

  • No TCP port enumeration, service banner scans, or network-wide discovery.
  • No SQL injection, XSS, authentication bypass, exploitation, fuzzing, or destructive payloads.
  • No directory brute force, admin-panel discovery, sensitive-file probing, or geolocation lookups.
  • No claim that a target is secure because the limited checks returned no findings.

Data handling and report storage

The latest report is stored in your browser's local storage so the separate report page can display it. The report cache is versioned and expires from the report-page view after 24 hours. There is no application database or account-based report history in this version. The target server receives the HTTP request from the hosted scanner infrastructure, and the hosting provider may process operational request logs under its own terms.

Avoid scanning URLs that contain secrets or personal data. Query strings and fragments are removed before the target request is made.

Interpretation and responsibility

Findings are indicators for manual review, not proof of exploitability. Missing headers or cookie attributes may be intentional in some contexts. A clean report does not mean the application has no vulnerabilities. You remain responsible for obtaining written authorization, staying within the approved scope, respecting rate limits, and complying with applicable law and the target owner's rules.

Do not use the service for denial of service, credential attacks, data extraction, persistence, or disruption.
